# Gorn v1.0.0

Go file apps you can run right now. This release provides standard Go source,
validated cached execution, standalone export, explicit cache management, and a
stdlib-only `sh` helper for exact arguments and supported shell execution.
The v1.0.0-rc.1 candidate exercises the same delivery gates before stable release.

## Install and verify

Install Go 1.26.4 or newer, then use a fixed module tag:

```sh
go install github.com/gornkit/gorn@v1.0.0
```

For the candidate, replace `v1.0.0` with `v1.0.0-rc.1`. Put Go's binary directory
on PATH. Alternatively download the matching release archive and SHA256SUMS.txt,
check its SHA-256 (Unix `sha256sum`/`shasum -a 256`, PowerShell `Get-FileHash`),
extract, and put `gorn`/`gorn.exe` on PATH. Run `gorn --version`, then follow the
[README](https://github.com/gornkit/gorn#your-first-script). Archives include Unix
executable permissions. Windows uses an explicit command, not a shebang association.

Go must remain on PATH for run/build, including warm hits. Exported programs need
neither Go nor Gorn, but retain their own command/data requirements. Five binary
targets are distributed; native release tests cover Linux amd64, macOS arm64 and
Windows amd64. Linux arm64/macOS amd64 are cross-built. Windows process-tree
cleanup is best effort; Unix process groups and bounded inherited-pipe waits do
not provide full shell job control. No cgo, go:embed, ambient workspaces, remote
script execution, registry, automatic update or package-manager integration is
included in v1.

## Upgrade from development versions

Use one complete `package main` and `func main()` in each `.gorn` file. Remove
`//gorn:main`; helpers can appear before or after main. There is no compatibility
grammar or automatic converter. Optional shebangs and header metadata remain.
User source and compiler diagnostic locations are preserved.

The supported Go library is `github.com/gornkit/gorn/sh`; former pre-v1 `pkg/`
implementation paths have moved behind `internal/` without forwarders. `sh.Cmd`
provides exact arguments; `sh.Exec` returns a status-only Result. Shell syntax,
quoting and failure behavior remain shell-specific. Consult the
[helper specification](https://github.com/gornkit/gorn/blob/main/docs/specs/gorn-sh.md).

Bundled helper source is the default. To use the published helper, select an
exact root version with `//gorn:require github.com/gornkit/gorn v1.0.0` and an
explicit `//gorn:go 1.26.4` floor. Dependencies require concrete versions; no
implicit latest/tidy/get operation occurs. First builds may need normal module
network access. Candidate scripts must use the candidate version instead.

Old cache layouts remain preserved and are not silently adopted/deleted. Current
build identity includes executable/helper/toolchain/profile digests; upgrades may
rebuild. Use `gorn cache list --json` for supported inspection instead of parsing
private files. Review `gorn cache clean --dry-run` before intentional deletion.
The compatibility, build/runtime, workflows and startup specifications describe
remaining limits and the measured 100 ms p95 reference-host warm budget.
